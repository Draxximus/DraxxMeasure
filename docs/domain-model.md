# Domain model

Phase 2 implementation details and the executable SQLite schema are described
in [the current capture contract](phase2.md).

## Relationships

```text
PartNumber ──< PartSpecification (immutable versions)
InspectionSession ──< InspectionItem >── PartSpecification
InspectionItem ──< Bundle ──< Measurement ──< MeasurementCorrection
```

An item fixes a Part Number and specification revision within a session. Many
items (including different Part Numbers) fit one session; many bundles fit one
item. A bundle is a **group**, matching one original spreadsheet column. Each
measurement is a position read top-to-bottom within that column.

## Types and invariants

| Type | Contract |
| --- | --- |
| `PartNumber` | Nonblank exact text; leading zeroes preserved; no implicit trim/case fold |
| `PartSpecification` | Immutable ID, positive per-part version, nominal/LSL/USL, positive resolution, mm unit |
| `InspectionSession` | ID, creation time, Active/Suspended/Closed status, optional closure time |
| `InspectionItem` | ID, session ID, Part Number, immutable specification ID |
| `Bundle` | ID, owning session/item, positive per-item sequence, nonblank label, Open/Closed state and times |
| `MeasurementInput` | Exact raw string and Abbreviated/FullLength mode |
| `Measurement` | Immutable ID, session/item/bundle/specification IDs, positive per-bundle sequence, raw input, interpretation/provenance, UTC capture time |
| `MeasurementCorrection` | ID, target original ID, optional previous correction ID, replacement or invalidation, nonblank reason, optional actor, UTC event time |
| `MeasurementHistory` | Original plus a validated ordered append-only correction chain; derived Original/Corrected/Invalidated status |
| `InspectionSnapshot` | One session item/specification at a commit revision, ordered bundles and complete measurement histories |

IDs, sequences, and versions are separate newtypes, each in `1..=i64::MAX`.
The compiler rejects substituting a bundle ID for a measurement ID. Their
constructors do not generate IDs or guarantee database uniqueness; storage does.
Request IDs are nonblank opaque strings, generated by a future adapter with
collision-resistant identity and persisted before retrying uncertain commands.

## Exact dimensions

`Length` stores a nonnegative `i64` count of nanometres. One mm is 1,000,000 nm;
the maximum is 9,223,372,036,854.775807 mm. Phase 1 accepts mm only and up to six
decimal places; finer resolution or other units need an explicit policy change.
This storage quantum is not a claim that an instrument measures nanometres.

Parsing accepts `[0-9]+(\.[0-9]{1,6})?` with an ASCII decimal point. Whitespace,
signs, exponents, locale commas, NaN/infinity, and Unicode digits are errors.
Overflow and excessive fractional digits (even trailing zeroes beyond six) fail
explicitly. No rounding occurs. Canonical display may remove insignificant zeroes;
the original text is retained independently and never replaced with that display.

`Resolution` is positive, and an accepted measured value must be an exact multiple
of it from zero. Nominal/limits need not be instrument ticks: they are engineering
parameters, not observations. Require `LSL < USL` and `LSL <= nominal <= USL`.
Nominal at a boundary is permitted; asymmetric tolerances are supported.

Simple conformance uses `value < LSL`, `value > USL`, otherwise within limits.
Limits are inclusive; display rounding and floating-point epsilon never influence
classification. Valid out-of-spec values can be recorded. Uncertainty guard bands
and validated measurement-system claims are explicitly not implemented.

## Original input and interpretation

Abbreviated input requires exactly two ASCII digits, retaining `01`. Full overrides
use `=9368.0`, retaining `=` and exact spelling. An interpretation records either
FullLength or IntegerMillimetreSuffix with policy name/version/bounds and whether
the operator explicitly selected among candidates. The result's value/mode/suffix/
bounds are checked; uniqueness is the reconstruction engine's responsibility.
See [reconstruction](reconstruction.md) for the unimplemented candidate algorithm.

## Time, order, and provenance

`UnixMillis` is a signed UTC epoch-millisecond quantity; adapters obtain/format it.
Clock corrections can move backwards, so timestamps are not sequence keys and
are not used to reject otherwise valid ordering. Capture sequence is per bundle;
bundle sequence is per item; commit revision gives persisted cross-bundle event
order. Exhausted counters fail instead of wrapping. Gaps remain visible; no
renumbering after invalidation or correction.

`BundleCapacity` limits effective observations to 42 and Closed bundles to 1..42.
It is checked using authoritative counts under the SQLite write lock. Undo retains
the original row and may free a slot; replacement capture uses a new sequence,
so historical row count/sequence can exceed 42 without violating active capacity.
Restoring an invalidated entry cannot increase the effective count above 42.

Instrument ID, calibration reference, and operator are optional factual metadata.
None means unknown, not calibrated, uncalibrated, or anonymous-by-policy. Unknown
uncertainty/resolution provenance must be surfaced in reports, not invented.

## Correction and snapshot semantics

Original observations never change. A replacement has its own raw input and
interpretation with the original specification's precision rules. Invalidation
removes the original from the **effective analysis population**, not from history.
An explicit replacement after invalidation restores an effective value. History
retains identity, original sequence/time, all intermediate events and reasons.
Only the last event supplies the effective value; events are not extra samples.

Storage checks the submitted expected previous event atomically, preventing
branching edits. Phase 1 design permits corrections only in Active sessions,
including closed bundles; Closed sessions are sealed. Later amendments require
an explicitly designed audited workflow, never an implicit reopen.

Read DTOs have public fields for adapters. `InspectionSnapshot::validate` checks
ownership, ID uniqueness, sequence order, and no open bundles in Closed sessions;
history construction checks event linkage. This is structural validation, not
proof of a database commit or a verified statistical result. Adapters must
reconstruct validated entities rather than blindly deserialize arbitrary fields.
Explicit `restore` constructors validate historical session/bundle state and
measurement content without incorrectly requiring a now-Closed session to be
Active. New-entry constructors still enforce capture lifecycle guards. Restoration
does not imply a new transition, authorize a write, or prove a prior database commit.
